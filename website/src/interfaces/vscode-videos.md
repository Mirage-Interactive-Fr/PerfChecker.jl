# VS Code video walkthroughs

Start with a performance question, run the relevant check, then inspect the
saved evidence. The walkthrough series follows that path in short chapters.
Each chapter has a written guide that you can follow independently of a video.

## Choose a chapter

| Chapter | What you will do | Written guide |
| --- | --- | --- |
| Introduction | Read a measured comparison and decide what to investigate next | [Investigate a workload](../guide/investigate.md) |
| 1 — Installation and a first result | Choose the Julia runtime and controller, run a TestItem, then open its result | [Configure VS Code](vscode-configuration.md) and [get a first result](vscode.md#Get-a-first-result) |
| 2 — Configure a comparison | Select checks, workloads and versions or commits before running a suite | [Design a suite](vscode.md#Design-a-suite-and-compare-targets) and [compare targets](../tutorials/comparisons.md) |
| 3 — Read measurements | Inspect distributions, allocations and profiles; check units and comparison limits | [Read saved plots](vscode-workflows.md#Plot-saved-results) and [understand measurements](../guide/understanding-measurements.md) |
| 4 — Choose an interface | Use the editor, a Julia REPL, Pluto or the Web interface for the same investigation | [VS Code workflows](vscode-workflows.md), [REPL and Pluto](repl-pluto.md) and [Web interface](web-studio.md) |
| 5 — Discuss and review a change | Select saved evidence, ask follow-up questions, review a proposal, verify it and restore when needed | [MCP advice and implementation](../mcp-advisor.md) |

Shorts focus on one action or result. They supplement these chapters; the
written guides contain the prerequisites, complete steps and recovery actions.

## Full tutorial

For the complete workflow, follow the chapters above in order. After your
first result, check the saved measurements before choosing another collector
or asking the advisor for an explanation. Preparing or applying an
implementation is an explicit action, separate from advice.

Before following a chapter, check the release requirements and platform scope in
[VS Code configuration](vscode-configuration.md) and
[qualification and reporting a problem](vscode.md#Qualification-and-reporting-a-problem).
